# 以原始文件指纹替代文件路径作为文件定位键

## 背景

img-search 的记录存储原以「原始文件路径」作为文件定位键。该设计存在根本缺陷：

- **路径不可靠**：文件被移动或重命名后，路径即失效，无法反查到对应记录。路径是易变属性，不适合作为持久标识。
- **元数据重复**：路径中的路径、文件类型、大小等信息，共享的文件索引服务已统一管理（其提取决策见 [`file-index-package-extraction.md`](../../../adr/decisions/file-index-package-extraction.md)），本工具再行保存形成双写。

## 核心决策

将文件定位键从「原始文件路径」替换为「原始文件的 BLAKE3 内容指纹」，并以其作为共享文件索引的关联键。存储结构调整采用破坏性重建（丢弃旧结构并重建），而非增量迁移。

### 双指纹设计

本工具在概念上维护两类指纹，分别对应「原始文件」与「处理后内容」两个层面：

- **原始文件指纹**（不要求唯一）：对原始文件内容计算，作为共享文件索引的关联键。两张仅 EXIF 等元数据不同的图片原始指纹不同，但因处理后内容相同可共用同一条记录。
- **处理后内容指纹**（要求唯一）：对预处理后（缩放、重编码、剥离 EXIF）的内容计算，作为视觉内容去重键。仅元数据不同的图片该指纹相同，重复处理时被跳过，避免对同一视觉内容重复索引（节省描述生成、向量化与索引写入的开销）。

### 接口变更

- 记录与插入类型中的「文件路径」字段替换为「原始文件指纹」字段。
- 按文件路径查询改为按原始文件指纹查询。
- 导入流程变更：先计算原始文件指纹，将文件登记至共享文件索引，再以该指纹作为本地记录的关联键。

## 权衡分析

**方案 A：保留文件路径，额外增加原始文件指纹**

- 优点：不丢历史数据，可渐进迁移。
- 缺点：文件路径与共享索引元信息双写，漂移风险持续存在；路径仍不可靠（移动/重命名后失效）。

**方案 B：以原始文件指纹替代文件路径**（已选择）

- 优点：单一关联键指向共享文件索引，元信息由共享索引统一管理；内容指纹不随路径变化，路径失效问题消除。
- 缺点：无法从本地记录直接反查文件路径，必须经共享文件索引间接获取；不提供历史数据迁移（破坏性重建）。

**不迁移历史数据的依据**：历史路径已不可靠（文件可能已移动），迁移其值没有意义。重建后重新导入即可——共享索引的去重与向量索引的写入均幂等，已索引的视觉内容会被唯一约束跳过，不会重复处理。

**原始文件指纹不设唯一约束的依据**：两张仅元数据不同的图片原始指纹不同但处理后内容相同。若对该指纹施加唯一约束，第二张图片会因冲突而失败；不设唯一约束，允许在处理后内容冲突时跳过第二张，仅保留首张的原始指纹。

## 影响范围

- **存储结构变更**（破坏性）：重建本地记录存储，历史数据丢失，需重新导入（去重与写入幂等，已索引内容自动跳过）。
- **接口变更（破坏性）**：记录与插入类型中的文件路径字段移除，替换为原始文件指纹；按路径查询改为按指纹查询。
- **导入流程变更**：导入时需先计算原始文件指纹并登记至共享文件索引。
- **搜索流程变更**：文件定位改为从本地记录的原始文件指纹经共享文件索引间接获取。
- 依赖 [`file-index-package-extraction.md`](../../../adr/decisions/file-index-package-extraction.md) 决策的共享文件索引服务。
