# img-classify — 图片互斥分类器（产品设计）

> 最后更新：2026-09-09

## 一句话

> 本文是**面向产品经理的产品设计**：说明产品解决什么问题、有哪些能力、按什么规则工作、与相邻工具如何区分。
> 项目/工具名为 `img-classify`；命令行二进制为 `imgclassify`（下文命令一律以 `imgclassify` 书写）。
> 实现层面的细节（模块结构、数据库表、配置文件、Prompt、算法等，对应 `docs/impl.md` §1–§13）见 [`docs/impl.md`](docs/impl.md)；已敲定的架构决策（决策编号 A1–A17 及其理由与代价）见 [`adr/features/img-classify.md`](adr/features/img-classify.md)。

## 1. 定位与目标

### 1.1 解决什么问题

用户本地有大量图片（相册、截图、素材、文档照），希望**按内容自动归类**，便于日后检索与统计。img-classify 每次对一张图给出**唯一一个类别**（例如「人像」「美食」「屏幕截图」）以及（厂商支持时的）**置信度**，分类结果落库后，可随时按类别筛选、看各类别分布。

### 1.2 它不是什么

**不做**以下事：

- **不做多标签**：一张图只归一个类别。需要一张图打多个标签的，见 `img-tagger`。
- **不做开放类别**：类别完全由「分类标准」预先定义，工具**不会**让 AI 自己发明新类别。
- **不做文件移动**：分类只是「只读地记下结论」，不修改也不移动原始文件。
- **不做聚类/自动发现新类别**：若未来想「自动帮我总结出有哪些类」，属另一工具 `img-cluster` 的范畴。

### 1.3 能力总览（子命令）

| 命令 | 做什么 | 是否需要联网调 AI |
|------|--------|------------------|
| `imgclassify <图片/目录>` | **图片分类**（核心，默认命令）：单张或一批图片自动归类 | 是 |
| `imgclassify search` | **查询**：按类别 / 置信度 / 日期等条件查已分类的图片 | 否 |
| `imgclassify stats` | **统计**：各类别分布，如各类多少张、平均置信度 | 否 |
| `imgclassify standards` | **标准管理**：列出 / 查看可用的分类标准 | 否 |
| `imgclassify images prune` | **清理**：清除失效类别残留 / 已失联的旧记录 | 否 |
| `imgclassify check` | **健康检查**：只读核对数据库与文件索引是否一致 | 否 |


## 2. 使用流程（用户视角）

### 2.1 分类一张/一批图片

对一张图：

```
imgclassify 照片.jpg            → 归为 photo-food（美食），置信度 0.93
```

对一批图（一个文件夹）：

```
imgclassify 旅行相册/ --recursive --progress  → 逐张分类：photo-food / 置信度 0.93，photo-scene / 置信度 0.88，…
```

批量处理时，每张图完成后立即显示结果（类别与置信度）；`--progress` 时在终端渲染实时进度条（已处理数 / 总数、当前文件名、失败数）。进度条不改变输出内容格式，仅改变终端呈现方式。

可控制的行为：

- **选哪套标准**：默认用内置的通用标准，也可指定其它标准。
- **是否跳过已分过的**：默认只分「还没按这套标准分过」的图，重跑不会重复扣费；也可强制全量重分。
- **先预览不落库**：`--dry-run` 只看结果，不写入记录。预览（`--dry-run`）时默认仍跳过已分图片；如需预览全部重新分类结果，可配合 `--mode full`。
- **是否要理由**：默认只返回类别；可要求模型**先给出简短中文理由、再给出类别**，便于人工抽查判断是否合理。

### 2.2 查询已分类的图

按需组合条件筛图，例如「全部人像」「置信度 ≥ 0.8 的美食」「排除某个类别」「某个日期之后」。空条件时直接列最近记录。

### 2.3 看统计

各类别分布统计。

### 2.4 管理分类标准 & 清理 & 体检

- `standards`：列出可用标准（含内置与自定义）。
- `prune`：标准改版后清理失效残留，默认先预览再执行。仅清理无理由依据的失效/漂移记录（`rationale` 为空），保留带人工判定理由的记录
- `check`：只读体检。

## 3. 关键产品规则

这些规则决定分类结果是否「可信、一致、可复用」。

### 3.1 一图一类、类别互斥

- 每张已分类图片只有一个类别值，且**必须**精确匹配所选分类标准里列出的类别。
- 一套标准内的类别彼此**互斥**（不语义重叠），AI 只在集合里**选一个**。
  - 互斥性由编写标准的人保证，工具不自动检测重叠。

### 3.2 类别来自「分类标准」，由人预定义

- 类别的“候选清单”不是用户随口给、也不是 AI 自由发挥，而是由一份**分类标准**规定。
- 工具**不自动补充兜底类别**：是否需要「其它/other」这一类，由标准作者决定是否写进清单。内置标准是否含 `other` 由该标准作者决定（默认标准含，见 §4.2）。如果标准里没有 `other`，而某张图确实归不进任何类，工具会视为这次判断失败并自动重试（见 §3.5），不会硬塞一个类。
- AI 若返回清单之外的类别名，同样视为失败并重试——保证入库的类别永远「干净、可统计」。

### 3.3 什么时候会「重新分类」

工具用「图片内容指纹 + 标准指纹」来判断一张图是否已经分过：

| 情况 | 结果 |
|------|------|
| 同一张图 + 同一套标准 | **跳过**（已分过，幂等，不重复扣费） |
| 同一张图 + 换了另一套标准 | **重新分类** |
| 同一张图 + 图片内容被修改（image_hash 变） | **重新分类** |
| 同一张图 + 标准内容被修改（standard_hash 变） | **重新分类** |
| 同一张图 + 换了模型/厂商 | **跳过**（去重键不含模型；换模型后如需重新分类请用 `--mode full`） |

### 3.4 置信度怎么看

- 置信度是 [0, 1] 区间内的实数，由模型对所选类别 token 的概率分布推算而来，**不是让 AI 自报信心**（自报通常不靠谱）。
- 受限于厂商能力，使用部分模型时拿不到这个概率，此时该条记录的置信度为「无」。
- 置信度为「无」的记录在查询/统计按阈值筛选时被排除（不计为命中，也不计为未命中）；统计均值同样不含它们。
- **入库不预设任何阈值**：没有「低于多少分就丢弃」的开关。置信度只是存下来，你要按什么标准筛（比如只看 ≥0.9 的），在**查询/统计时**临时指定即可——每次都可以不同。
- 关闭置信度采集后，所有记录没有置信度，工具其余功能不受影响。

### 3.5 判断失败的兜底

- 单张图失败不影响同批其它图（批处理逐张隔离）。
- 当 AI 返回的类别非法/缺失/格式不对时，工具会在**单张内自动重试几次**（额外重试最多 2 次，共最多 3 次尝试）；仍失败则记为失败、不进库。
- 联网调用类错误由底层按厂商规则自动重试。

## 4. 分类标准（可配置的分类规则）

### 4.1 什么是「分类标准」

一份「分类标准」就是：**这套分类用哪些类别 + 每个类别怎么界定**。它是产品的核心可配置项——换一套标准，就等于换一套分类口径。

### 4.2 默认标准：通用 12 类

开箱即用提供一套**通用标准**，按内容题材划分，共 12 个类别：

1. 人像（含人类主体）
2. 场景 / 风景
3. 动物
4. 美食
5. 文档照（书页 / 笔记 / 合同扫描等）
6. 商品 / 物品特写
7. 艺术创作（画作、插画等）
8. 屏幕截图
9. 手写 / 简笔画 / 草图
10. 图形 / 图表 / logo
11. 动画帧
12. 其它（兜底）

> 大多数类别配有「包含什么 / 排除什么」的明确说明，供 AI 与使用者对齐口径（详单见 `docs/impl.md` §3.2 的内置默认标准全文）。

### 4.3 自定义标准

用户可按需写自己的标准（例如公司内部把截图再细分）。放入指定目录（如 `~/.img-data/classify-standards`，见实现文档 §3.3）即可使用；自定义标准与内置标准 **frontmatter `name` 同名时，自定义覆盖内置**。

### 4.4 与其它工具的类别差异

| 对比维度 | img-val | **img-classify** | img-tagger |
|---|---|---|---|
| 一张图出几个值 | 两个数（估值区间） | **一个类别** | 多个标签 |
| 类别/标签从哪来 | 无此概念（数值） | **预定义于标准**（封闭） | 开放（AI 可新建） |
| 冲突处理 | 无 | 无（封闭+一图一类，不会冲突） | 有（标签冲突自动解决） |
| 定位 | 图片估值 | **图片归类（分类）** | 图片打标（开放标签） |
三者可同时使用、彼此不冲突：用 `img-classify` 做**粗粒度分类**，用 `img-tagger` 做**细粒度打标**，二者通过同一份文件索引关联但不共享存储；`img-val` 估值与另两者互不干扰：估值输出数值区间，不涉及类别/标签。

## 5. 性能要求与限制

| 约束项 | 限制值 | 说明 |
|--------|--------|------|
| 最大并发数 | 3（默认） | `--concurrency N` 可调，相同图片哈希串行，不同图片可并行 |
| 单张最大尺寸 | 最长边 1568 px | 送 LLM 前自动缩放（按比例，保持宽高比） |
| 支持图片格式 | jpeg / png / webp / gif | 默认标准的 `image_formats` 提示，不强制过滤；无法解码的格式按图片错误处理 |
| 分类标准类别数 | 无硬上限 | 实际受 LLM 上下文窗口与约束解码能力限制 |
| 批量规模 | 无硬上限 | 受磁盘空间与模型额度限制 |
| 模型响应时间 | 不适用 | 取决于模型与图片复杂度，无硬性保证；批量时受并发数与 API 限流影响 |
| 存储空间 | 不适用 | SQLite WAL 模式；仅存元数据，不含图片本身 |

> 以上默认值可在 `imgclassify.toml` 中调整（详见 `docs/impl.md` §7）。

## 6. 错误处理与边界情况

| 场景 | 处理方式 |
|------|----------|
| AI 返回非法/缺失类别 | 见 §3.5 |
| AI 返回类别不在标准集合内 | 见 §3.5 |
| 文件不存在或无法解码 | 单图前置校验失败，跳过该图并报错 |
| 图片尺寸超出限制 | 自动缩放至最长边 1568 px（见 §5） |
| 网络/模型 API 错误 | 按厂商内置重试策略自动重试（见 §3.5） |
| 批处理中单张失败 | 单张失败不影响其它图（见 §3.5） |
| 数据库写入冲突 | 先删后插（`uq_class_hash_standard` 唯一索引） |
| file-index 未登记 | 分类成功后自动注册 |

> 详细的失败处理与日志机制见 `docs/impl.md` §6。

## 7. 边界与不变量小结

- 只读不变量：分类只读地记录结论，不修改也不移动原始文件。
- 类别干净性保证：入库类别值全部来自所选标准清单，不含 AI 新造类别，可放心统计。
- 已确认无待定项：本产品的产品规则（类别组织、重试次数、查询语法、内置类别数、是否支持 sync 模式等）均已定稿，不再有「待确认假定」。

## 8. 术语表

| 术语 | 定义 |
|------|------|
| **BLAKE3** | 一种高速加密哈希算法，用于生成文件内容的唯一指纹；本工具通过 BLAKE3 值与 `file-index` 模块关联，实现分类记录与原始文件的链接 |
| **logprobs（对数概率）** | LLM 在生成每个 token 时输出的对数概率值；`logprobs: true` 时 API 返回各 token 的 `logprob`（以 e 为底的自然对数概率），可用于衡量模型对特定输出的确定程度 |
| **约束解码（constrained decoding）** | 在 LLM 生成过程中强制限制输出符合预定义 JSON Schema 的技术；OpenAI 通过 `response_format` 参数实现，生成期即排除非法输出；实现仍保留后验校验兜底（Anthropic 必做，OpenAI 亦校验） |
| **置信度（confidence）** | 本工具中指通过对类别 token 的 logprobs 派生的 [0, 1] 区间实数，反映模型对该分类结果的确定程度 |
| **分类标准（standard）** | 定义一套互斥类别及其界定规则的 Markdown 文件；包含 frontmatter 元数据（名称、类别 ID 列表）与 body（每类别的详细描述） |
| **幂等** | 同一输入重复执行产生相同结果的特性；本工具中，同一图片 + 同一标准再次分类时自动跳过，不会重复扣费 |
| **image_hash** | 处理后图片内容的 SHA-256 指纹，用于判定同一图片是否已分过 |
| **standard_hash** | 分类标准全文的 SHA-256 指纹，用于判定标准是否变更（触发重新分类） |
| **厂商（provider）** | 提供 LLM API 的服务商（如 OpenAI、Anthropic）；实现文档中以 provider 指代 |
