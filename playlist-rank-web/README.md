# playlist-rank-web

歌单排序器：粘贴歌单（每行一首 `歌名 - 歌手`），填写**歌曲解析 API**（GET 模板，
直接返回音频流），用 [`<media-rank>`](../media-rank-web/) 两两比较手动排出前 k 名
（k 留空 = 全部精确排序），导出排名文本或 `.m3u8` 播放列表。纯手动、无 LLM、
纯前端（无服务端）。

## 多歌单与有序约束

支持同时输入多个歌单（「+ 添加歌单」），每个歌单可勾选**有序**（默认无序）：

- 参与排名的候选是所有歌单歌名的并集（跨歌单重复的歌名只保留一份，会提示）；
- **有序歌单的相对顺序会保留在最终排名中**：锦标赛人工比较决定整体名次，
  收束时对结果做稳定拓扑重排——有序歌单内部的先后关系不被破坏，其余部分
  尽量保持锦标赛序；若某次裁决与有序歌单的顺序相反，会提示最终排名将以
  歌单顺序为准；
- **冲突**：两个有序歌单对同一对歌曲给出相反顺序（直接或经多首传递）时
  约束成环、无解，开始排名前即报错并列出无法同时满足的歌名，请检查输入。

## 使用

```sh
pnpm dev    # http://localhost:5173
```

1. **歌单**：可添加多个，每个歌单可勾选「有序」；每行一首
   `歌名 - 歌手`（歌手可省略，只写歌名亦可），自动 trim、滤空行、单歌单内去重；
   跨歌单重复保留一份并提示。歌名与歌手在去重、排序、排名、导出中都作为整体
   出现，同名不同歌手视为两首不同的歌。每个歌单右侧的 **⇄** 按钮逐行交换
   ` - ` 前后的内容（`歌手 - 歌名` ⇄ `歌名 - 歌手`）——从别处粘贴时常把两者
   写反，一键纠正比逐行改省事；**不含 ` - ` 的行保持原样**，因为那类行只有歌名、
   没有可交换的另一侧。
2. **歌曲解析 API**：GET URL 模板，`{name}` 占位符被替换为 URL 编码后的歌名，
   `{artist}` 被替换为歌手（输入未给歌手时该占位符整体消失，不留空参数）。
   替换后的 URL 就是音频直链（API 直接返回音频流）。例如：
   `http://127.0.0.1:5178/audio?name={name}&artist={artist}`
   （见 [song-resolve-api](../song-resolve-api/)）。
3. **找出前 k 名**：输入框留空或填全部（k ≥ 歌单并集长度）时走 **Ford-Johnson
   精确全排序**（≈ n·log₂n − 1.44n 次比较，产出经认证的严格全序）；填一个
   更小的 k（1 ≤ k < n）时走 **前 k 名提取**（knockout 定冠军 + 胜者树逐名
   提取，≈ n + k·log₂n 次比较，只有前 k 名保证正确）。两种方式都是每次比较
   自动连播后点击"更好"即裁决。
4. **只播重听**（可选）：勾选后不做排序，只按当前歌单顺序**相邻试听** n−1 次，
   确认顺序对不对；判定为"这一首比上一首更好听"处即标为顺序错误，**不改变**
   原顺序。适合导入的已有歌单本身带顺序、先听一遍核对。比较次数固定 n−1。
5. **开始排名**：全部歌曲进入 `<media-rank>` 音频对局，得到完整排名（前 k 名
   经认证，其余为提取顺序的延拓，且保持有序歌单的相对顺序）。结果以**播放列表
   形态**呈现，可「▶ 从头连续播放」按排名序逐首播放。
5. **导出**：
   - 复制排名（每行一个歌名，排名序）；
   - 下载 `playlist-ranked.m3u8`（`#EXTM3U` + `#EXTINF` + 解析直链）。

表单内容（全部歌单 + k 值 + API 模板 + LLM 配置）会记忆在 localStorage，刷新后
恢复；旧版单歌单表单自动迁移为第一个无序歌单。

## 中断恢复

每次裁决后，对局的**完整状态快照**（当前候选、待裁决对、已完成裁决）自动存入
localStorage（连同所属的歌单并集与 k 值）。刷新或关闭页面后重新打开，若歌单与
k 值与快照一致，页面会显示「恢复进度」——点击即从上次继续，对局与已做裁决
完全不变；「丢弃」则清除快照重新开始。排名完成后的快照同样保留，刷新后可恢复
到排名视图继续导出。

之所以保存完整快照而非裁决记录：前 k 名模式的初始配对由确定性种子洗牌产生，
重放裁决无法重建同样的对局，只有序列化整个状态机才能精确续排（见
media-rank-web 的 ADR）。

## 从图片提取歌单

播放列表截图可直接转成歌单：点「从图片提取」选择图片（或直接 Ctrl+V 粘贴
截图），多模态 LLM 提取歌曲后**追加**到输入框，人工修正后再开始排名。

- 需要在「图片提取设置」中填写 **OpenAI 兼容**的多模态 LLM API：API 地址
  （如 `https://api.openai.com/v1`，自动补全 `/chat/completions`；**不能以 `/`
  结尾**，输入框用 `pattern` 约束）、API Key、模型名；
  线协议与 `@llm-image/shared` 的 OpenAI provider 一致（text + image_url 块）。
- 提示词要求模型**每行输出一首 `歌名 - 歌手`**：能确认歌手时必须写出，确实
  无法确认时才只输出歌名（不得编造、不得留空 ` - `）。同时要求忽略界面 UI 文本
  （应用名、按钮、时长、播放量、进度条、水印等），只输出歌曲。客户端再做一层
  清洗（剥代码围栏、去编号与列表符号、滤空行），歌名中的数字（如 "24K Magic"）
  不受去编号影响。
- **截断处理**：图中文字被界面截断而带省略号（`…` 或 `...`）时，只保留可见
  文字、剥除省略号——被截掉的部分无从得知，补全只会得到无法检索的串。行中间
  的省略号（`寻…记得`）同样剥除；剥除后残留的尾部 ` - ` 一并去掉。只认 `…` 与
  三个点，**两个点不动**（`Hey Jude..`、`I.E.D.` 等歌名不受影响）。
- 图片在发送前缩放到长边 ≤1600px 的 JPEG，控制请求体积。
- Key 仅保存在本机 localStorage；API 需允许浏览器跨域（OpenAI 官方与多数
  兼容网关支持）。

## 拖拽导入

把内容直接拖到歌单区域（拖入时显示虚线框）：

- **文本**（选中的歌名列表）→ 清洗后**追加**到最后一个歌单；
- **文本文件**（.txt/.csv/.list/.m3u/.m3u8）→ 每行一首，**新建歌单**
  （文件名作歌单名）；
- **截图/图片文件** → 走「从图片提取」的多模态 LLM 流程，结果追加到最后
  一个歌单。

拖到具体某个输入框内的文本由浏览器原生插入光标处，不做额外处理。

## 说明

- 纯前端直连：解析 API 的音频直链由浏览器 `<audio>` 直接播放（media 元素
  不受 CORS 限制），因此该 API 无需配置跨域；但不发送 Referer/Cookie 之外的
  任何自定义头，需要鉴权的 API 不适用。
- 直链不可用时对应歌曲的卡片播放器会原生报错，不影响其余歌曲排名。
- 悬停预览 / 缩略图参数（`zoom`）对音频无意义，本包的 MediaSource 实现忽略之。
- **编辑曲目标识的副作用**：本包的候选 id 就是「歌名 - 歌手」整行，音频直链由
  id 经模板展开得到，因此在排名中改 id 等于换了一首歌。若该项已裁决，改 id 会
  丢弃其裁决并回退重做——且**前 k 名模式下签表由 id 派生，改任一 id 会使全部
  裁决失效、从头开始**（见 media-rank-web 的 ADR 3e）。改 id 后，有序歌单的
  顺序约束按 id 匹配，该曲的约束关系将不再命中，需重新开始排名并复查歌单。
  只改名称/元数据则不影响裁决，但**直链会跟着显示名走**：本包按名字展开 URL
  模板，所以在排名中把「晴天 - 周杰伦」改成「稻香 - 周杰伦」，播放的就是稻香。

`pnpm lint`、`pnpm build`。
